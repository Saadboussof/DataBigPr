**What this means:** 
Your Spark script successfully read the Porto Taxi Kaggle dataset (`train.csv`). It found **1.71 million rows (trips)**. Spark inferred the following structure (schema) for the data:

### Porto Taxi `train.csv` Column Explanations
* **`TRIP_ID`**: A unique numerical identifier for each specific taxi trip.
* **`CALL_TYPE`**: How the trip was initiated. Usually:
   * **`A`** = Central Dispatch (Phone call to headquarters).
   * **`B`** = Taxi Stand (Customer retrieved the taxi at a designated stand).
   * **`C`** = Street Hail (Flagged down on the street).
* **`ORIGIN_CALL`**: If `CALL_TYPE` = `A`, this contains a scrambled ID of the customer who called. Otherwise, it is null.
* **`ORIGIN_STAND`**: If `CALL_TYPE` = `B`, this contains the ID of the physical taxi stand where the trip started.
* **`TAXI_ID`**: A unique scrambled identifier for the specific taxi vehicle driving the trip.
* **`TIMESTAMP`**: A numerical Unix Timestamp (seconds since Jan 1, 1970) marking the exact moment the trip began.
* **`DAY_TYPE`**: Indicates what type of day it was:
   * **`A`** = Normal working day.
   * **`B`** = Holiday.
   * **`C`** = Day before a holiday. 
* **`MISSING_DATA`**: A Boolean (`True` or `False`). If `True`, it means the GPS tracker broke or lost signal during the trip, so the route data is incomplete. (Our script filters these out!)
* **`POLYLINE`**: A giant JSON list of GPS Coordinates `[Longitude, Latitude]`. A new coordinate is recorded exactly every **15 seconds** during the trip. This is the core data used to trace the route on your map and estimate trip durations!
